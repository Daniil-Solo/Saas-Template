## Описание фич

Здесь хранятся текстовые описания фич с предложениями по реализации. Агент читает их перед реализацией новой функциональности. Если фича меняет состав системы или модель данных, то изменения сначала вносятся в диаграммы `docs/architecture/`.

Один файл - одна фича: `docs/usecases/<название_фичи>.md`. Рекомендуемая структура:

```markdown
# Название фичи

## Цель
Какую задачу пользователя решает фича.

## Пользовательский сценарий
Пошаговое описание: кто, что делает и что получает в результате.

## Предложение по реализации
- Сущности и поля БД
- Эндпоинты (метод, путь, права доступа)
- Бизнес-правила и обработка ошибок
- Внешние сервисы и фоновые задачи

## Вне рамок
Что намеренно не делаем в этой фиче.
```
