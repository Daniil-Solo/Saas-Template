## Описание фич

Здесь хранятся общие для backend и frontend текстовые описания фич с предложениями по реализации. Агент читает их перед реализацией новой функциональности. Если фича меняет состав системы, модель данных, страницы или маршруты, то изменения сначала вносятся в диаграммы (`docs/deployment.md`, `backend/docs/architecture/`, `frontend/docs/architecture/`).

Один файл - одна фича: `docs/usecases/<название_фичи>.md`. Рекомендуемая структура:

```markdown
# Название фичи

## Цель
Какую задачу пользователя решает фича.

## Пользовательский сценарий
Пошаговое описание: кто, что делает и что получает в результате.

## Предложение по реализации

### Backend
- Сущности и поля БД
- Эндпоинты (метод, путь, права доступа)
- Бизнес-правила и обработка ошибок
- Внешние сервисы и фоновые задачи

### Frontend
- Страницы и маршруты (путь, доступ: публичный / авторизованный / admin)
- Состояния экрана: загрузка, пусто, ошибка, успех
- Формы, валидация, тексты ошибок
- Адаптивность и доступность (если есть особенности)

## Вне рамок
Что намеренно не делаем в этой фиче.
```
