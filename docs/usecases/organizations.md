# Организации, приглашения, роли и права

## Цель
Дать пользователям общее рабочее пространство: создать организацию, пригласить в неё коллег и управлять тем, что каждый из них может делать. Это основа для будущих функций продукта, которые будут принадлежать организации и зависеть от прав участника.

## Участники и роли
- **Пользователь** — любой зарегистрированный человек. Может состоять в нескольких организациях и создавать новые.
- **Создатель организации** — пользователь, создавший её. В своей организации может всё: назначает роли, приглашает, исключает. Он не может покинуть организацию и не может быть исключён.
- **Участник** — состоит в организации. Всегда видит её и список участников. Остальное зависит от его ролей.
- **Роль** — именованный набор прав. У участника может быть несколько ролей, его возможности — сумма прав всех его ролей.
- **Администратор системы** — единственный, кто создаёт роли и решает, какие права в них входят. Не связан с конкретными организациями.

Права в первой версии:
- **Управление участниками** — менять роли участников и исключать их.
- **Управление приглашениями** — создавать, просматривать и отзывать приглашения.

## Пользовательский сценарий
1. **Создание организации.** Пользователь указывает название и становится её создателем. Роли ему не нужны: у создателя неограниченные права.
2. **Настройка ролей** (администратор системы). Админ создаёт роли и выбирает права для каждой, позже может изменить или удалить роль. При удалении роль пропадает у всех участников.
3. **Приглашение.** Создатель или участник с правом управлять приглашениями вводит email и выбирает роли, которые получит приглашённый. Система выдаёт ссылку-приглашение; письмо не отправляется, ссылку передают сами.
4. **Принятие.**
   - Приглашённый открывает ссылку. Если он не вошёл, ему предлагают войти или зарегистрироваться и затем возвращают к приглашению.
   - Принять приглашение может только пользователь с тем же email, на который оно выдано.
   - После принятия пользователь становится участником с ролями из приглашения.
5. **Управление участниками.** Создатель или участник с правом управлять участниками меняет роли участника или исключает его.
6. **Выход.** Любой участник, кроме создателя, может сам выйти из организации.
7. **Переключение.** Пользователь с несколькими организациями выбирает, с какой работает сейчас.

## Бизнес-правила и ограничения
- Роли общие для всей системы, а не свои в каждой организации.
- Права определяются только ролями; исключение — создатель организации.
- Приглашение действует 7 дней, потом истекает. Его можно отозвать. Принять можно один раз.
- На один email в организации одновременно может быть только одно действующее приглашение. Пригласить того, кто уже в организации, нельзя.
- Чтобы пригласить заново, прежнее приглашение отзывают и создают новое.
- Ссылка показывается один раз при создании, затем её можно получить только создав приглашение заново.
- Если роль из приглашения удалена до принятия, пользователь вступит без неё.
- Участник с правом управлять участниками может назначить любую роль, даже с правами, которых нет у него самого.
- Пользователь не видит чужие организации и не узнаёт о их существовании.
- Действие без нужного права завершается понятным отказом.

## Требования к интерфейсу
- **Переключатель организаций** в шапке: список организаций пользователя, выбор текущей и «Создать организацию». Выбор запоминается между визитами.
- **Создание организации:** форма с названием.
- **Участники:** список участников с их ролями; для тех, у кого есть право, — смена ролей и исключение; для остальных — только просмотр; у не-создателя — кнопка «Выйти».
- **Приглашения** (видно при наличии права): список с состоянием (действует, принято, отозвано, истекло), создание (email и роли), копирование ссылки, отзыв.
- **Страница приглашения:** кто и в какую организацию приглашает, с какими ролями; кнопка «Принять». Для невошедшего — переход к входу/регистрации с возвратом.
- Возможности, на которые у пользователя нет прав, скрываются.
- Для каждого экрана: загрузка, пустое состояние (например, «У вас пока нет организаций»), ошибка с понятным текстом, успех.
- Управление ролями администратором в интерфейсе не делаем (см. «Вне рамок»).

## Вне рамок
- Отправка писем с приглашениями.
- Переименование и удаление организации, передача владения.
- Собственные роли внутри отдельной организации.
- Интерфейс администратора для ролей и прав.
- Права на предметные данные будущих функций, журнал действий, лимиты на число участников.
